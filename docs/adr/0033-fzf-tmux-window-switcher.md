# ADR 0033: fzf で tmux のウィンドウを検索して切り替える (Ctrl-E)。コマンド選択 (Ctrl-O) には全コマンドを出す

ステータス: 採択→キーの割り当て (Ctrl-E) は[ADR 0036](0036-tmux-window-switcher-on-ctrl-t.md)

## 文脈

tmux のウィンドウ (タブ) が増えると、`prefix + p` / `n` で順に移ったり、番号を覚えて移ったりするのが手間になる。
fzf でウィンドウの一覧をインクリメンタルに絞り込み、選んだウィンドウへ切り替えたい。キーは `Ctrl-E` にする。

- zsh は vi モード (`bindkey -v`) で、挿入モードの `Ctrl-E` には割り当てが無い (`self-insert`)。
- `zsh/fzf.sh` には、fzf を使う zsh のウィジェット (`repo`・`fbr`・`fkill` など) を `bindkey` で割り当てる仕組みがある。

あわせて、コマンド選択 (`fzf_command_finder`、`Ctrl-O`。[ADR 0031](0031-command-finder-key-and-rust-tools-via-mise.md)) の一覧を見直す。

- コマンド選択は、選んだ名前 `<名前>` に対して関数 `__<名前>` を実行し、その出力を入力行に足す。
- 一覧は関数の中に手で書いた 15 個の名前で、`zsh/fzf.sh` に `__` 付きの関数を足しても一覧には出ない。
  新しく足すコマンド (このウィンドウの切り替え) も、手で書き足さないと出てこない。

## 実装すること

- `zsh/fzf.sh` に zsh のウィジェット `ftmux_window` を足し、`bindkey "^e" ftmux_window` で割り当てる。
- 一覧は `tmux list-windows -a` で、すべてのセッションのウィンドウを出す。1 行の形式は次のとおり。

  ```
  <セッション>:<ウィンドウ番号>  <ディレクトリ名>  <実行中のコマンド>
  ```

  - ディレクトリ名は、そのウィンドウで選択中のペインのカレントディレクトリの末尾 (`#{b:pane_current_path}`)。
    ステータスラインのウィンドウの表示 ([ADR 0007](0007-tmux-status-directory-name.md)) と揃える。
  - 今いるウィンドウには印 (`*`) を付ける。
- fzf のプレビューに、そのウィンドウで選択中のペインの画面 (`tmux capture-pane -ep`) を出す。
- 選んだら `tmux switch-client -t <セッション>:<ウィンドウ番号>` で切り替える (別のセッションのウィンドウにも移れる)。
  選ばずに抜けたら何もしない。
- 一覧・切り替えの本体は、ほかのコマンドと同じく `__ftmux_window` という関数にし、`ftmux_window` はそれを呼ぶだけにする。
  `__ftmux_window` は何も出力しない (コマンド選択から呼んだときも、入力行に何も足さない)。
- tmux の外 (`$TMUX` が空) で押したときは、何もせずに入力行へ戻る。
- 入力途中の行は変えない (`LBUFFER` に何も足さない)。
- `docs/specifications.md` の zsh のキーの表に `Ctrl-E` を足す。

### コマンド選択 (Ctrl-O) に全コマンドを出す

- `fzf_command_finder` の一覧を、手書きの名前ではなく、`zsh/fzf.sh` で定義している `__` で始まる関数すべてから作る。
  - 定義した場所は zsh の `$functions_source` (関数名 → 定義したファイル) で調べる。`zsh/fzf.sh` の場所は、
    読み込み時に `${(%):-%x}` で取っておく。
  - fzf 本体 (`fzf --zsh`) が定義する `__fzfcmd` などは、別の場所で定義されているので一覧に出ない。
  - 一覧には `__` を外した名前を出す。選んだときの動き (`__<名前>` を実行し、出力を入力行に足す) は変えない。
- 一覧の各行に、名前・キーの割り当て・説明を並べる。

  ```
  repo                           ^G  ghq のリポジトリを選び、パスを入力行に足す
  docker_stop_container              docker のコンテナを選んで止める
  ```

  - キーの割り当て: 名前と同じ zsh のウィジェット (`__` を外した名前。`repo`・`fbr` など) に割り当てられているキーを、
    現在のキーマップ (`bindkey -M main`。vi モードでは vi 挿入モード) から引く。割り当てが無ければ空欄にする。
  - 説明: `zsh/fzf.sh` の各 `__` 付きの関数の直前の行に、`# ` で始まる 1 行のコメントで書く。
    一覧を作るときに `zsh/fzf.sh` を読み、関数の定義の直前のコメントを取り出す。コメントが無ければ空欄にする。
  - 今ある 15 個と `__ftmux_window` のすべてに、説明のコメントを書く (既存のコメントは説明として読める形に直す)。
  - 選んだ行から先頭の名前を取り出して `__<名前>` を実行する。
- これにより、今の 15 個に加えて `ftmux_window` が出る。今後 `zsh/fzf.sh` に `__` 付きの関数を足せば、自動で一覧に出る。
- 一覧を作る処理は関数 `fzf_command_names` に分け、`zsh/tests/fzf-command-finder.test.zsh` でテストする。
  `fzf_command_names` は 1 行に 1 コマンドを「名前・キー・説明」の順で出す。
  一覧に出さないよう、名前に `__` を付けない。CI の zsh のテストに足す。

## 実装しないこと

- nvim など zsh 以外のプログラムを動かしているときの切り替え。`Ctrl-E` は zsh の入力行でだけ効く
  (どこからでも使うには、tmux の割り当てと `display-popup` で同じことをする必要がある。必要になったら別の ADR にする)。
- ペイン単位の切り替えと、ウィンドウの作成・削除。
- fzf 本体のウィジェット (`fzf-file-widget` など) をコマンド選択に出すこと。

## テスト設計

- ウィンドウの切り替えはシェルスクリプトで、tmux と fzf の操作が中心のため、自動テストは書かない
  (共通の指示の TDD の対象外)。一覧を作る処理だけは、既存の zsh のテストと同じ形で自動テストを書く。
- 別の tmux サーバー (`tmux -L`) にセッションとウィンドウを複数作り、次を確かめる。
  - 一覧のコマンドが、すべてのセッションのウィンドウを上の形式で出し、今いるウィンドウに印が付くこと。
  - 一覧の 1 行から取り出した `<セッション>:<ウィンドウ番号>` が、`switch-client -t` に渡せる形であること。
- zsh で `bindkey -M viins '^E'` が `ftmux_window` であることを確かめる。
- `zsh/tests/fzf-command-finder.test.zsh` (CI で実行):
  - `zsh/fzf.sh` を読み込むと、`fzf_command_names` が `zsh/fzf.sh` の `__` 付きの関数をすべて (`__` を外して) 出すこと。
  - 別のファイルで定義した `__` 付きの関数 (fzf 本体の `__fzfcmd` に相当) は出ないこと。
  - 同名のウィジェットにキーが割り当てられていればそのキーを、無ければ空欄を出すこと。
  - 関数の直前の `# ` のコメントを説明として出し、コメントが無ければ空欄を出すこと。
  - `zsh/fzf.sh` のすべての `__` 付きの関数に説明があること (説明の書き忘れを防ぐ)。
- 実際に `Ctrl-E` で一覧が出て、選んだウィンドウに切り替わること、プレビューが見えることは本人が確かめる。

## トレードオフ

- 独自の zsh の関数が増える。
- zsh の入力行でしか使えない (nvim の中などでは `prefix + p` / `n` などを使う)。
- 挿入モードの `Ctrl-E` を、今後ほかの用途に使えなくなる。
- コマンド選択には `zsh/fzf.sh` の `__` 付きの関数がすべて出るため、補助のための関数も `__` を付けると一覧に出てしまう。
  一覧に出したくない補助の関数は、`__` 以外の名前にする必要がある。
- `$functions_source` は zsh 5.4 以降の機能。
- 説明は関数の直前のコメントという書き方の約束に頼る。約束を破ると説明が空欄になる (テストで検出する)。
- `Ctrl-O` を押すたびに `zsh/fzf.sh` を読む (数百行なので、体感できる遅さにはならない)。
