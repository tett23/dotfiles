# ADR 0119: Claude Code が文脈に受け取る Bash の出力を 10000 文字までにする

ステータス: 採択

## 文脈

本人から、トークンの使用量を減らすよう頼まれた。Claude Code では、長いコマンドの出力がそのまま文脈に入り、以後のターンで毎回読み直される。
たとえば、この ADR を書いたセッションでは、`vscode/settings.json` の 667 行の差分や、Codex の実行ファイルの `strings` の結果が、そのまま文脈に入った。

調べたことは次のとおり (Claude Code のドキュメント)。

- 設定 `bashOutputMaxChars` は、成功した Bash のコマンドの出力のうち、文脈に受け取る文字数を決める。超えた出力はファイルに保存され、Claude は短いプレビューとファイルのパスを受け取る。
  値は `4000` から `128000` に収められる。設定しないときは 30000 文字まで受け取る。Claude Code v2.1.261 から使える
  (https://code.claude.com/docs/en/settings-reference.md の `bashOutputMaxChars`)。
- プレビューは、先頭から 2000 文字までである。残りが要るときは、Claude がファイルを読むか検索する (https://code.claude.com/docs/en/tools-reference.md の「Output limits」の表)。
- 失敗したコマンドの出力は、約 10000 文字までを受け取り、超えると、作業ファイルから読み戻した範囲 (読み戻しの窓) から、先頭と末尾を合わせて約 10000 文字抜き出す (同じ表)。
- `bashOutputMaxChars` は、文脈に受け取る上限と、読み戻しの窓の大きさを一緒に決める (同じページの「Output limits」の節の本文)。
  そのため、10000 にすると、読み戻しの窓も 30000 文字から 10000 文字に縮み、失敗したコマンドの抜粋の切り出し元も小さくなる。窓を出力の先頭から取るか末尾から取るかは、ドキュメントに書いていない。
- `bashOutputMaxChars` を設定すると、環境変数 `BASH_MAX_OUTPUT_LENGTH` は無視される (settings-reference の同じ節)。
- 手元の Claude Code は、デスクトップアプリが 2.1.317 (`claude-code/2.1.317`)、`flake.nix` の `pkgs.claude-code` が 2.1.318、PATH の先頭の `claude` が 2.1.322 (`claude --version`) で、どれも v2.1.261 以降である。

本人は、まず 10000 文字にし、使ってみて後で調整すると決めた。

## 実装すること

- `.claude/settings.json` に `"bashOutputMaxChars": 10000` を足す。
- `docs/specifications.md` の Claude Code の節に書く。README は変えない。

## 実装しないこと

- 環境変数 `BASH_MAX_OUTPUT_LENGTH` を設定すること。`bashOutputMaxChars` があると無視される。
- Codex の出力の上限を変えること。この ADR は Claude Code の設定だけを扱う。
- 失敗したコマンドの、文脈に受け取る上限 (約 10000 文字) を変えること。設定では変えられない。

## 不変条件

なし。Claude Code の設定の値だけを決める ADR で、出力を切る振る舞いは Claude Code が決める。

## テスト設計

設定の変更なので、CI の自動テストは書かない。実装の後に、新しいセッションで次を確かめる。

- `jq .bashOutputMaxChars .claude/settings.json` が `10000` になる。
- 次の入力で、返る形を確かめる。

  | 入力 | 出力の文字数 | 返る形 |
  | --- | --- | --- |
  | `true` | 0 | 空のまま返る |
  | `seq 1 1500` | 6393 | そのまま返る |
  | `seq 1 2221` | 9998 (ちょうど収まる) | そのまま返る |
  | `seq 1 2222` | 10003 (少しあふれる) | ファイルに保存され、先頭 2000 文字までのプレビューとパスが返る |
  | `seq 1 3000` | 13893 | 同上 |
  | `seq 1 3000; false` | 13893 (失敗) | 先頭と末尾の抜粋が返る。抜粋が出力の先頭寄りか末尾寄りかを記録する |

- 上限を超えた出力が、保存されたファイルから読めることを確かめる (`seq 1 3000` のファイルを読む)。

## 結果

- `.claude/settings.json` に `"bashOutputMaxChars": 10000` を足した。設定は、開いていたセッションにもすぐ効いた。
- テスト設計の表の入力で確かめた。

  | 入力 | 返った形 |
  | --- | --- |
  | 出力の無いコマンド | 「no output」とだけ返った |
  | `seq 1 2222` (10003 文字) | ファイルに保存され、パスと先頭 2000 文字までのプレビュー (`1` から `527`) が返った |
  | `seq 1 3000; false` (13893 文字、失敗) | 終了コード 1 と、出力の先頭から約 10000 文字 (`1` から `2221` と `22`) が返った。末尾 (`2222` から `3000`) は返らず、ファイルのパスも無かった |

- 失敗したコマンドの抜粋は、出力の先頭から取られた。長い出力の末尾にあるエラーの行は、文脈に入らない。失敗しうる長いコマンドは、`2>&1 | tail -n 50` のように末尾を絞って動かす。
- `seq 1 1500` と `seq 1 2221` (収まる場合) は、約 6000 から 10000 文字を文脈に入れるだけの確かめなので、トークンを節約するため動かしていない。

## トレードオフ

- 長いログや差分を読む作業では、ファイルを開くためのツールの呼び出しが増える。
- 失敗したコマンドの長い出力は、読み戻しの窓が 10000 文字に縮むので、今より狭い範囲からしか抜粋されない。窓が出力の先頭から取られるなら、末尾のエラーの行が抜粋に入らないことがある。テスト設計の `seq 1 3000; false` で確かめ、困るなら値を上げる。
- 値は使いながら調整する。調整するときは、新しい ADR を書く。
