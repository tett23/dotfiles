# ADR 0145: サブエージェントの報告と、指示者への報告を削る

Status: accepted

## 文脈

2026-11-18 に、指示者 (エージェントに作業を頼んだ人) は、トークンを節約するために、サブエージェントの不要な報告と応答を削りたいと求めた。
指示者に見せるのは、判断が要るときと、重要な進捗のときだけでよい、とも求めた。

今の決まりは、サブエージェントに返す形 (動かしたコマンド、数値、`file:line`) を指定させる ([ADR 0111](0111-claude-agents-in-dotfiles.md)、`.claude/CLAUDE.md` の「任せるときの決まり」)。
しかし、返す形の外にあるもの (前置き、頼まれた内容の言い直し、手順の語り、締めの要約や申し出) を削る決まりは無い。
そのため、サブエージェントの報告は、根拠のほかの文でふくらみ、それを読むメインのエージェントのコンテキストを使う。

指示者への報告にも、決まりが無い。
メインのエージェントは、ふつうの手順の進み具合や、サブエージェントの報告の中身を指示者に書くことがある。
指示者は、それを読む必要が無い。

## 調査した事項

- `.claude/agents/runner.md` は「結果だけを短く返す」「出力全体は返さない」と書く。前置きと締めの文を削る決まりは無い (`.claude/agents/runner.md:8`、`:14`)。
- `.claude/agents/reader.md` と `.claude/agents/auditor.md` には、短く返す決まりが無い。
- `.claude/agents/auditor.md` は「問題が見つからなかった項目も、確かめたことを一行で書く」と書く (`.claude/agents/auditor.md:13`)。
- Codex の役割 (`codex/agents/*.toml`) は、Claude Code のエージェントと同じ指示を `developer_instructions` に持つ ([ADR 0117](0117-codex-model-roles.md))。
- `.claude/CLAUDE.md:117` と `codex/AGENTS.md:118` は、「指示者への報告」を既定のモデルで行うと書く。いつ報告するかは書かない。
- `.claude/CLAUDE.md` と `codex/AGENTS.md` は、`auditor` の結果を要約し直さずに「指示者に示す」と書く。
- 「指示者」は、エージェントに作業を頼み、報告を受ける人である ([ADR 0146](0146-requester-and-maintainer-terms.md))。

## 実装すること

1. `.claude/agents/` の 3 つのエージェントと、`codex/agents/` の 3 つの役割の指示に、次の一項を足す。
   「答えと根拠だけを返す。前置き、頼まれた内容の言い直し、手順の語り、締めの要約、次の作業の申し出を書かない。」
2. `.claude/CLAUDE.md` と `codex/AGENTS.md` の「任せるときの決まり」に、次の二項を足す。
   - 任せるときは、返す形に加えて、返す量の上限 (件数、行数) を指定する。受け取ったことを伝えるだけ、礼を言うだけのメッセージを、サブエージェントに送らない。
   - サブエージェントの報告は、指示者にそのまま示さない。指示者への報告に要る結論と根拠だけを使う。`auditor` の指摘は、今の決まりのとおりそのまま示す。
3. `.claude/CLAUDE.md` と `codex/AGENTS.md` の「モデルの使い分け」の節に、「### 指示者への報告」の小節を足し、次のとおり書く。
   - 指示者に書くのは、判断が要るとき (決めること、承認、先へ進めない理由) と、重要な進捗のとき (頼まれた作業を終えた、長い作業の段を終えた、計画を変える失敗が起きた) だけにする。
   - ふつうの手順の進み具合、ツールの出力、サブエージェントの報告の中身は書かない。
   - 作業を終えたときの報告は、変えたこと、確かめた結果、残ったことだけを短く書く。
4. 仕様書のサブエージェントの段落に、この決まりを一文で書く。

## 実装しないこと

- `auditor` の「問題が見つからなかった項目も一行で書く」は変えない。監査の記録は、どこを確かめたかが残ることに意味があるためである。
- `auditor` の指摘を、指示者にそのまま示す決まりは変えない。
- 精読 (`close-reading`) や監査のスキルの報告の形は変えない。報告の形がスキルで決まっているものは、スキルに従う。
- 指示者への報告の文字数の上限は決めない。判断が要るときに要る説明の量は、事柄によって違うためである。

## 不変条件

なし。
エージェントへの指示の文だけを決める ADR であり、入力に対して成り立つ性質を書けないためである。

## 受けいれ条件

- A1: `.claude/agents/` の 3 つのファイルと `codex/agents/` の 3 つのファイルが、実装すること 1 の一項を持つ。
- A2: `.claude/CLAUDE.md` と `codex/AGENTS.md` が、実装すること 2 の二項と、3 の小節を持つ。
- A3: 次にサブエージェントに作業を任せたとき、返った報告に前置きと締めの文が無いことを確かめる。

## テスト設計

- A1、A2: `grep -c` で、各ファイルに足した文があることを数える。設定の文なので、自動のテストは書かない。
- A3: 手で確かめる。実装の後に `runner` か `reader` に作業を一つ任せ、報告の最初と最後の文が答えか根拠であることを見る。確かめるまで、ロードマップの「手で確かめる項目」に載せる。

## トレードオフ

- 報告を削ると、サブエージェントが何を確かめなかったかが見えにくくなる。根拠のコマンドと出力を返す決まりは残すので、確かめたことは根拠から読める。
- 指示者への報告を減らすと、指示者は作業の途中を追いにくくなる。重要な進捗は報告するので、途中で方向を直す機会は残る。
