# ADR 0055: 改善案 (2026-10-13) のおすすめ・その後に気づいた点と、監査の残りの一部を直す

ステータス: 採択

## 文脈

[dotfiles の改善案 (2026-10-13)](../audit/2026-10-13-improvements.md) のうち、「おすすめ」(I1〜I5)・「その後に気づいた点」(I6〜I11)
と、「前回の監査で残っている項目」の T9・Z6・Z10・V4・V6・N6・N10 を直す (V4 は I4、V6 は I3 と同じ。T4 は直さない)。
直し方を決めるために調べた結果は次のとおり。

- **I1** `~/.ghcup` が 33GB。ghc は 11 版入っていて、使っているのは ghcup の既定の 9.14.1 ([ADR 0050](0050-ghc-cabal-via-ghcup.md))。
  VSCode の Haskell の拡張は ghcup の推奨の版 (ghc 9.10.3・HLS 2.14.0.0・cabal 3.16.1.0) を使う設定 (`vscode/settings.json`)。
  ほかに HLS が 6 版、cabal が 5 版入っている。
- **I2** tmux は、`Shift+Enter` などの修飾キーの組み合わせを、既定ではペインのプログラムに渡さない (`extended-keys` が off)。
  `extended-keys on` と、外側の端末の機能の宣言 (`terminal-features` の `extkeys`) で渡せるようになる。
  Ghostty の `Cmd+P` (Super 付きのキー。監査の O3) は、tmux が Super を扱えるかで結果が変わり、実際に試すまで分からない。
- **I3** nvim 0.11 から、診断のメッセージを行の中に出す表示 (`virtual_text`) が既定で無効。今は記号と下線だけ。
- **I4** `<Leader>fmt` は LSP で整形し、保存時の整形 (conform。prettier など) と結果が違う。
- **I5** git の便利な設定 (`commit.verbose`・`rebase.autosquash`・`branch.sort`・`column.ui`・`push.followTags`) が無い。
- **I6** `~/.cargo/bin` に、手元のリポジトリから `cargo install` した `send-to-kindle`・`shorten-path`・`shorten_path`・`adr-guard` がある。
  PATH では mise の版が先なので使われていない。`adr-guard` は cargo の版 (v0.2.1) のほうが mise の版 (v0.1.0) より新しい。
- **I7** `zsh/langs/swift.sh` は `TOOLCHAINS=swift` を設定するが、Swift の toolchain は入っていない (効いていない)。
  `zsh/exports.sh` の gcloud の PATH の分岐も、`~/google-cloud-sdk` が無く使われていない。
  `zsh/langs/scala.sh` は Coursier の PATH を足していて、Coursier (`cs`・`amm`) は入っているので使われている
  (改善案の「効いていない」は誤り)。
- **I8** nvim 0.12.6 が出ている。Nix の更新 (`bin/update-nix`。sudo が要る) で上がる。
- **I9** 監査レポートの ADR の参照はリンクになっていない。監査レポートはコミット後に変更しない。
- **I10** CI の adr-guard の検査を、意図したコミット済みの ADR の書き換えで通す手段が無い。adr-guard は別のリポジトリ。
- **I11** `~/.nix-profile/bin` は、nix-darwin の `NIX_PROFILES` の既定から PATH に入る。
- **T9** tmux の prefix を `C-q` にした後も、既定の `prefix + C-b` (`send-prefix`) の割り当てが残っている。
- **Z6** `LANG`・`EDITOR`・`XDG_*`・`MISE_TRUSTED_CONFIG_PATHS` が `zsh/exports.sh` (zshrc から読む) にあり、`zsh -c` など非対話のシェルに
  届かない。PATH 以外の export は、すべての zsh が読む `zsh/zshenv` に置ける (PATH を zshenv に置かない理由は
  [ADR 0010](0010-fix-zsh-fzf-audit.md) の path_helper の件で、それ以外には当てはまらない)。
- **Z10** fzf-tab の README が勧める `zstyle ':completion:*' menu no` (zsh の補完の一覧の選択を止め、fzf-tab に任せる) と、
  グループの見出し (`zstyle ':completion:*:descriptions' format '[%d]'`。fzf-tab のグループの切り替えに使う) が無い。
- **N6** Xcode Command Line Tools の待ち合わせが `install.sh` と `bootstrap.sh` にあり、`bootstrap.sh` は Enter を押して待つ
  (`read`)。`install.sh` は 5 秒ごとに確かめる (`curl | sh` では stdin で待てないため)。
- **N10** 監査の時点 (2026-10-11) では Command Line Tools が 14.3 (2023 年) で、リンカも古かった。今は解消している。
  `xcode-select -p` は `/Applications/Xcode.app/Contents/Developer` で、Command Line Tools も 27.0 になっている。
  `clang` は Apple clang 21.0.0、`ld -v` は `PROJECT:ld-27037.1` (新しいリンカの ld-prime)。`softwareupdate --list` に開発ツールの更新は無い。

## 実装すること

### dotfiles の設定

| 案 | 変更 |
|---|---|
| I2 | `tmux/tmux.conf` に `set -s extended-keys on` と `set -as terminal-features ',*:extkeys'` を足す |
| I3 | `nvim/lua/config/options.lua` で `vim.diagnostic.config({ virtual_text = true, severity_sort = true })` にする |
| I4 | `nvim/lua/config/keymaps.lua` の `<Leader>fmt` を `require("conform").format({ async = true, lsp_format = "fallback" })` にする |
| I5 | `git/config` に `commit.verbose = true`・`rebase.autosquash = true`・`branch.sort = -committerdate`・`column.ui = auto`・`push.followTags = true` を足す |
| I7 | `zsh/langs/swift.sh` と、それを読む `zsh/zshrc` の行を消す。`zsh/exports.sh` の gcloud の分岐を消す (`scala.sh` は残す) |
| T9 | `tmux/tmux.conf` に `unbind C-b` を足す |
| Z6 | `LANG`・`EDITOR`・`XDG_*`・`MISE_TRUSTED_CONFIG_PATHS` の export を `zsh/exports.sh` から `zsh/zshenv` に移す (PATH と、PATH に頼る `MANPAGER` は `exports.sh` に残す) |
| Z10 | `zsh/completions.sh` に `zstyle ':completion:*' menu no` と `zstyle ':completion:*:descriptions' format '[%d]'` を足す |
| N6 | `bootstrap.sh` の待ち合わせを、`install.sh` と同じく 5 秒ごとに確かめる形にする (Enter を押さなくてよい) |

- `docs/specifications.md` の tmux・nvim・git の記述を直す。

- **I1** ghcup で、次を消す (`ghcup rm`)。既定の ghc 9.14.1・cabal 3.18.1.0 と、VSCode が使う推奨の ghc 9.10.3・HLS 2.14.0.0・
  cabal 3.16.1.0 は残す。
  - ghc: 9.0.2・9.2.2・9.2.4・9.2.5・9.4.2・9.4.3・9.4.4・9.4.8・9.10.1 (約 17GB)
  - HLS: 1.7.0.0・1.8.0.0・1.9.0.0・2.7.0.0・2.9.0.1
  - cabal: 3.6.2.0・3.8.1.0・3.10.3.0
- **I6** `cargo uninstall send-to-kindle shorten-path shorten_path adr-guard` で、使われていない cargo の版を消す。
  mise の `adr-guard` を最新に上げる (`mise upgrade adr-guard`)。

## テスト設計

- 設定の変更が中心のため、自動テストは書かない。既存の zsh のテスト (`zsh/tests/`) がすべて通ること。
- I2: 別の tmux サーバーで設定を読み込み、`extended-keys` が `on`、`terminal-features` に `extkeys` があること。
  実際に tmux の中の Claude Code で `Shift+Enter` が改行になるか、nvim で Ghostty の `Cmd+P` が効くかは本人が確かめる
  (`Cmd+P` は効かない可能性がある)。
- I3・I4: nvim をヘッドレスで起動し、`vim.diagnostic.config().virtual_text` が `true`、`<Leader>fmt` が conform を呼ぶこと。
- I5: `git config --get` で 5 つの設定が読めること。
- I7: 新しい zsh で `TOOLCHAINS` が無く、Coursier の PATH は残っていること。
- T9: 別の tmux サーバーで設定を読み込み、`list-keys -T prefix` に `C-b` が無いこと。
- Z6: `zsh -c 'echo $EDITOR $LANG $XDG_CONFIG_HOME'` (非対話のシェル) で値が出ること。新しい対話シェルでも同じ値であること。
- Z10: 新しい zsh で `zstyle -L` に 2 つの設定があり、`cd <Tab>` などの fzf-tab の補完が従来どおり動くこと (本人が確かめる)。
- N6: shellcheck が `bootstrap.sh` で通ること。待ち合わせの関数を、`xcode-select -p` が成功する状態で呼んで、すぐ返ること。
- N10: `xcode-select -p`・`clang --version`・`ld -v` が文脈に書いた版であること (この ADR を書く時点で確かめた)。
- I1: `ghcup list -c installed` に、残す版だけがあること。新しい zsh で `ghc`・`cabal` の版が変わらないこと。
- I6: `cargo install --list` に 4 つが無く、新しい zsh で `send-to-kindle`・`shorten-path`・`adr-guard` が mise の版で動くこと。

## トレードオフ

- I1: 消した ghc の版を使うプロジェクトがあれば、ghcup で入れ直す必要がある (ダウンロードに時間がかかる)。
- I2: 修飾キーの送り方が変わるので、ペインのプログラムによっては、これまでと違うキーとして受け取ることがある。
- I3: 診断のメッセージが行の右に出るので、画面の情報量が増える。
- I5: `git branch` の並びが最近更新した順になり、一覧が複数列で出る。`git push` で注釈付きのタグも送られる。
- I6: cargo の版 (手元のリポジトリからの開発中の版) は使えなくなる。開発中の版を試すときは、改めて `cargo install` する。
- T9: `prefix + C-b` (`C-b` をペインに送る) が使えなくなる。`C-b` はそのまま押せばペインに届く。
- Z6: `zsh/zshenv` は、zsh のスクリプトを含むすべての zsh が読むので、そこに置く設定は軽く保つ。
