# ADR 0105: Z3 を Nix で入れる

ステータス: 採択

## 文脈

本人から、Z3 も入れるよう頼まれた ([ADR 0103](0103-java-and-alloy.md) で Java と Alloy を入れた続き)。
Z3 (https://github.com/Z3Prover/z3) は Microsoft Research の SMT ソルバーである。

調べたことは次のとおり。

- 今の手元に `z3` は無い (`command -v z3` は何も返さない)。
- Z3 のリリース (GitHub の `Z3Prover/z3`): 最新は `z3-5.3.3` (2026-10-29)。macOS の Apple Silicon 向けの zip (`z3-5.3.3-arm64-osx-13.3.zip`) もある。
- dotfiles の `flake.lock` の nixpkgs の `z3` は 5.3.2 (最新より 1 つ前)。`bin/z3` を持ち、出力は `out`・`lib`・`dev`・`python`。
  `nix build` はビルド済みのものを取ってきて、`z3 --version` は `Z3 version 5.3.2 - 64 bit`。
  `(declare-const x Int)(assert (> x 3))(check-sat)(get-model)` を `z3 -in` に渡すと、`sat` と `x` = 4 のモデルを返した。
- mise の登録簿に Z3 は無い (`mise ls-remote z3` は「z3 not found in mise tool registry」を返す)。

## 実装すること

- `dependencies.md` の「Install CLIs」に `z3` を足す。
- `flake.nix` の `home.packages` に `pkgs.z3` を足す。
- `darwin-rebuild switch` で入れる (sudo が要るので、本人が実行する)。
- `docs/specifications.md` の「依存の管理」に書く。README は依存の一覧を dependencies.md に任せているので変えない。

## 実装しないこと

- 最新の 5.3.3 を GitHub のリリース (mise の github バックエンド) から入れること。ほかの CLI と同じく Nix で入れ、`bin/update-nix` で nixpkgs に合わせて上げる。
- Z3 の言語のバインディング (Python の `z3-solver`、Java の jar など)。要るときにその言語の道具で入れる。
- nvim で SMT-LIB (`.smt2`) を書くための設定。

## テスト設計

依存の追加なので、CI の自動テストは書かない。実装の前に次を実行して今の値を確かめ (上の「文脈」)、実装の後にもう一度実行して確かめる。

- `nix build .#darwinConfigurations.dione.system` が通る (`darwin-rebuild switch` の前)。
- `darwin-rebuild switch` の後、`command -v z3` が home-manager のプロファイルを指し、`z3 --version` が 5.3.2 (nixpkgs の版) を返す。
- 上の「文脈」の SMT-LIB の問題を `z3 -in` に渡すと、`sat` を返す。

## 結果

- 実装の前: `command -v z3` は何も返さない。
- `nix build .#darwinConfigurations.dione.system` は通り、ビルドしたシステムの依存に `z3-5.3.2` が入った。
- 本人が `darwin-rebuild switch` をした後: `command -v z3` は `/etc/profiles/per-user/tett23/bin/z3`、`z3 --version` は `Z3 version 5.3.2 - 64 bit`。
  上の「文脈」の問題を `z3 -in` に渡すと、`sat` と `x` = 4 のモデルを返した。

## トレードオフ

- 版は nixpkgs に合わせるので、Z3 の最新のリリースより遅れることがある (今は 5.3.2 で、最新は 5.3.3)。
