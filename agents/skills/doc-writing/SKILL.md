# 文書の書き方

README、仕様書、ADR、マニュアルなど日本語と英語の文書は、パラグラフライティングで書く。

読み手は文書ごとに次のとおりとし、その読み手が知らないことを前提にせずに書く。

- 仕様書と ADR: 本人、コントリビューター、会話の文脈を持たずに文書だけを読む AI。
- README: そのリポジトリについて何も知らない人。
- マニュアル: そのソフトウェアやプロダクトに初めて触れる人。

書き方は次のとおり。

- 一つの段落には一つのトピックだけを置く。いくつものトピックや手順が混ざった長い段落は分ける。
- 段落の最初の文でその段落のトピックを示す。最初の文だけを拾い読みしても、論の流れを追えるようにする。
- 前の段落との論理の関係を、段落の頭の接続の言葉で示す（しかし、そのため、実際、であれば など。英語では However、Therefore など）。
- 一文には一つの事柄だけを書く。主語と述語を対応させ、「これ」「その」が何を指すかを明らかにする。
- 関係する内容は一つの節にまとめ、用語は使う前に定義する。定義した用語は、文書の中で別の語に言い換えない。
- 列挙の性質のものは箇条書きか表にする。ただし、短い列挙は文の中に書いてよい。脇道の補足は本文ではなく脚注に下ろす。
- 論は一方向に進める。主張を置き、反論を処理し、結論は一度だけ置く。
- 確かめた事実と、推測や意見を分けて書く。確かめていないことは「未確認」と書く。
- 意味を足さない言い回し（「〜することができる」「重要なのは」「〜と言えるでしょう」など）を使わない。
- 仕様書・README・マニュアルを組み直すときは、振る舞いを変えず、落とさず、弱めず、足さない。数値、診断のコード、キー、既定値、ADR へのリンク、アンカーがすべて残ることを、書き直す前と後の一覧で確かめる。コミットした ADR は組み直さない（ADR の節を参照）。
- 書いた後に、各段落の最初の文だけを読み通し、論の流れが追えるかを確かめる。
